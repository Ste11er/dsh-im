# QQ 短期上下文图片修复

## 根因与修改

短期缓存原本只保存正文，纯图片因正文为空被丢弃；后续提问仅提交当前消息的图片。当前 `volc/deepseek-v4.1-flash` 配置已声明支持 text/image，无需改模型。官方能力依据见[火山图片理解文档](https://docs.volcengine.com/docs/ark/image-understanding?lang=zh)，真实回答质量仍需实际提问验证。

- QQ 适配层复用 `qqInboundMessage`，只在访问策略允许后暂存惰性图片来源，不在未 @ 时下载、调用模型或回复。
- 短期缓存保存纯图片及带文字图片引用，继续使用每群 20 条、15 分钟、100 群及 8 KiB 文字预算。图片引用与文字共用快照、群隔离、过期和关闭失效规则。
- 被 @ 时在本地命令和交互处理后合并图片，当前消息优先，历史图片按最新顺序填充现有 IM 图片数量额度；`imageIndexes` 标明本轮对应序号，`omittedImages` 标明未提供的图片。JSON 不包含下载 URL。
- 通过现有 HarnessClient 的原图保存、大小校验、图片内容块、模型接纳和错误处理流程传递，未新增 OCR 或专用模型调用。原图一旦进入问答，其生命周期沿用已有工作区附件设置。
- 更新面板与使用说明；没有修改长期数据库、访问权限、模型设置或共享 Harness 生产逻辑。
