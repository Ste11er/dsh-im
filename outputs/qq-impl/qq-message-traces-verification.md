# AstrBot 借鉴首轮：QQ 逐条消息轨迹

日期：2026-10-31。实施依据：[可行性与分批实施](../../docs/方案/AstrBot可借鉴内容可行性与实施.md)。本次只实施首项，未启用长期记忆、语音、入站限流或向量服务。

## 已实现

QQ 设置中新增“逐条消息轨迹”：开启采集、按结果筛选、查看时间线、下载脱敏诊断 JSON。默认关闭，关闭后停止新增采集但保留内存中已有诊断。HMAC 标识关联接收→访问判定→上下文→接话判断→真实宿主 Session/Turn→工具更新→发送/回执。失败、未知、安静、继续听、忙时丢弃、冷却合并分别记录；发送错误提示不覆盖原始失败结果。

每机器人最多 256 条、每条 64 个事件、24 小时有效期；导出最多 50 条。满容量淘汰旧元数据，超事件预算保留最新阶段并增加截断计数，不限制消息处理。机器人重连保留 controller 中轨迹，Host 重启清空。关闭/重新开启后，旧一代异步回调不能继续写入。

字段限定为阶段/结果枚举、时间、计数和不可逆标识。正文、提示词、工具参数/输出、原始群/成员/Session/Turn/工具名、错误正文、路径、URL、配置及凭据均不进入记录或导出。不新增联网调用和模型调用，不复制上游代码。

## 自动化证据

专项覆盖真实 QQ bridge 的正常发送、等待/保持安静、多群隔离、忙时丢弃、确定失败/结果未知、冷却延后判断上下文归属，以及采集开关、晚到回调、容量/过期、RPC 校验、重连/重绑保留、面板筛选/详情/JSON 下载动作。

共享 HarnessClient 的新增可选 onTurn 回调通过真实 tracker 与当前 prompt 关联，专项测试验证只报告当前回合。关闭采集时 QQ 继续使用原 ask 路径，不订阅新增进度。

本机单进程 1000 次轨迹记录约 42ms（约 0.042ms/条），不是生产群聊端到端延迟结论。未使用性能阈值隐藏失败。

真实部署接口验证还发现工作区包装层使返回值异步化，新增 RPC 漏 await 导致空导出。现已修复并把生产同款工作区包装加入专项；目录数据只附加到账号快照，不进入诊断详情或导出，完整回归再次执行。首次接口验证失败未宣称功能完成，QQ 连接仍正常。

初次全量回归发现重复判断事件与一处英文投影缺失，已修正后重跑。包校验要求开关沿用选择控件，已采用与熟识度相同的下拉选择，没有放宽检查脚本。

## 本轮明确未实现

SQLite 持久化、ZIP/原始日志导出、其他渠道轨迹、未到达 QQ WebSocket 的消息追踪。快捷命令/审批等现有专用状态机只记录入站与处理终态，不宣称拥有普通模型问答相同的完整阶段。工具仅展示哈希标识和阶段，不展示参数。

## 用户验收

部署后打开 DSH → IM → QQ → 当前机器人设置 → “逐条消息轨迹”，选择启用。群里 @ 发送普通问题，收到回复后点击“查看／刷新轨迹”和“查看时间线”；再发送不 @ 的自然群聊，核对接话判断结果；下载 JSON 检查无聊天正文。真实平台验收通过后再进入下一功能。
