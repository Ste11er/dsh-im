# QQ 主动接话：语义完整性与图片输入验收

日期：2026-10-25。范围经用户确认：只用于未 @ 的主动接话；被 @ 的普通聊天继续立即走原回复流程。

后续用户要求放宽语义完整性判断，当前规则与实测见[语境判断调整](qq-contextual-judgment-verification.md)；本报告保留最初实现的验收过程。

## 需求与根因

用户希望同一人的拆分发言合起来理解，模型认为意思完整后再回应；不能用连续消息停止或固定静默时间判断说完。同时修复主动接话看不到图片。

原判断协议只有回复/安静，既不能表达“继续听”，也没有按人保留未完成发言。判断中或冷却中的新输入原来直接跳过。图片被 `!text` 和 `maxImages: 0` 排除，实际共享群 Session 的 ask 也没有收到 images。

修复前新增回归运行失败 4 项：纯图片不触发；没有未完成发言读取接口；判断中新输入未被再评估；原生判断器拒绝 WAIT。命令：`node --test --test-isolation=none test/channels/qq/semantic-participation.test.mjs test/channels/qq/context-images.test.mjs`。

## 变更与契约

- 判断结果增加 `[[QQ_WAIT_MORE]]`，独立统计“继续听”；完整但不适合插话仍为安静，真实失败仍为错误。
- `QqGroupContext` 按发言人读取未处理片段。已经回复/放弃的发言转为背景；已回答的 @ 提问不会再次成为当前输入。其他人的消息和机器人自己的输出作为背景保留。
- 未完成发言共享既有短期缓存边界：20 条/群、512 字符/条、8192 UTF-8 字节注入、15 分钟保留、100 群。没有新增长期原文存储或无限等待缓冲。
- 判断阶段新输入使旧判断失效，本群仅保留最新待评估候选。回调开始执行时读取最新片段；旧判断晚返回不能调用共享 Session 生成回答。冷却计时器晚执行时也只评估最新候选，该并发问题另有先红后绿的回归。
- 定时器只执行已有候选的模型调用冷却；无新输入时 WAIT 不会重新评估或自动回复。当前已保存的冷却仍为 1 秒，不随每条消息重置。真正生成回答时继续沿用忙时不排队规则。
- 纯图片可触发判断。判断器经过下载校验、图片压缩和 Host 附件准入接收真实图片；共享群 Session 的 Harness ask 接收延迟图片源。本次发言图片优先，其后为近期背景图片，imageIndexes 对应实际顺序。
- 同一次判断/回复复用原图下载结果，回合后释放字节；缓存只保存懒加载源。图片下载失败、超限或模型服务失败不伪装成正常安静。
- 若判断或回复模型仅支持文字，复用已配置的图片总结模型生成标注来源的转述；此转述不写入长期记忆，也不依赖记忆开关。所选图片总结模型必须支持看图，否则明确失败。
- 原有群 Session 绑定、按回合限制工具、访问策略、发送预算、回复窗口检查和表情本地缓存规则保留。

影响文件：group-participation、group-context、qq-bridge、原生 group-participation-reply、production 接线；image-prompt 提取原有图片准入逻辑供图片总结/判断共享；设置面板、英文投影、说明文档及回归测试同步。无配置 schema 或数据库迁移。

## 部署与恢复

沿用当前 DSH 的精确 argv、环境与工作目录，先备份配置、工作区和 Session 绑定，受控重启后检查实际连接。当前回复与判断仍为官方 Flash Off；长期记忆保持原已启用状态，165 条归档、18 条摘要，不因本次功能改动开关或改写旧档案。

如后续群测发现不可接受的重复接话或持续等待，可先在既有设置中关闭群聊自主参与，取消待处理候选，保留 @ 回复和现有数据。需要运行版本回滚时，`outputs/runtime/qq-semantic-participation/before-build/` 保留本次修改前的两份 lib 产物，恢复后按当前进程身份校验再受控重启；不覆盖其后产生的配置、会话或记忆。源代码修复与构建需要同步处理，避免下一次构建重新覆盖回滚产物。本次未执行回滚。

## 用户实群检查建议

不 @，先发“大肥鱼，我想问一下”，稍作停顿确认未因停顿自动回答，再发“为什么零不能做除数？”，观察是否合并回答一次。另发送含明确数字的图片和完整提问，检查回复能否正确引用图片内容。被 @ 的原回复路径不需要等待语义判断。
