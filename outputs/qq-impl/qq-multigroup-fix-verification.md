# QQ 多群接收与 @ 去重修复

日期：2026-10-29。状态：**可复现的 @ 去重缺陷已修复并部署；异常群平台接收情况等待实群输入核验，不宣称两类问题已全部验收。**

## 已确认与未确认

本机当前群聊自主参与开启、冷却 1 秒、短期群聊上下文开启、账号未暂停、群聊天访问策略为 open，两个已有群对应两个不同的 DSH Session。没有发现本地“仅最活跃群”的配置。不能根据这些设置证明 QQ 会向所有群下发普通消息。

建立回归 `node test/channels/qq/mention-redelivery.test.mjs`，真实桥接流程中先处理 `GROUP_MESSAGE_CREATE` 并让接话判断保持安静，再输入同 ID 的 `GROUP_AT_MESSAGE_CREATE`。修复前期望一次实际回复，得到零次，断言明确失败；修复后通过。这证明存在一种足以造成漏 @ 的处理顺序，不证明用户最近每一次未响应都来自该路径。

原因：普通群事件开始判断时就调用 `markSeen`，后续专用 @ 事件被同 ID 去重吞掉。修复将消费标记移到实际接管回复、进入生成/发送之前；仅判断安静/等待不消费，后到的真实 @ 可以取消判断并进入普通问答。实际回复已经开始的消息继续标记和去重，失败或未知状态也不因重推再次生成/发送。忙时丢弃继续按既有规则，不恢复积压队列。

## 群级接收证据

设置页新增“各群消息接收诊断”，最多保留最近 100 个群的无正文计数，区分 SDK 入站事件类型与本地 @ 识别、访问拒绝、普通背景、判断、等待/静默、实际回复与忙时丢弃。此限制仅约束诊断，不影响业务群处理范围。

第一次接入时假设 SDK 的 `rawEvent` 同时广播已解析消息；上线观察发现已识别 @ 计数有值、raw 计数无值。核对当前 QQ SDK 的 gateway dispatcher 确认其 message 与 raw 是互斥分支，因此修正为在第一个消息中间件清理/归一化前记录保留的事件类型。回归亦改成只走 SDK 实际 message 契约，先见失败再修复；没有用伪造 rawEvent 来证明真实接收。

其他群只有 @ 能到、普通事件一直未观察到时，需在目标群实际发送普通消息并核对 QQ 全量消息接收设置。诊断只表述“尚未观察到”，不把无事件当作已确认平台拒绝。需要由群管理者在 QQ 侧开启的能力无法靠 DSH 本地接话开关伪造；本次没有擅自修改 QQ 平台授权。
