# 长期记忆图片转文字

日期：2026-10-24。用户要求先让 Agent 总结图片为文字，再与长期记忆的文字一起保存。沿用「长期记忆等用户自己开」约束，部署不启用该开关，不做真实图片模型调用或群消息发送。

## 实现

- 新增 Host 图片描述工厂，通过当前 Host 的 `agents.create` 创建独立 Agent 与 Session。使用机器人所选或 Host 默认模型，并确认视觉能力；图片沿用既有下载白名单、大小和数量限制，压缩预算沿用 IM 图片设置，再通过 `attachments.admitPromptContent` 接纳为真实图片附件。
- 独立 Agent 使用完整识图提示词，工具呈现切为 native、allowlist 为空并设置拒绝执行 guard；通过 `agent/request` 限制一步模型请求，1200 输出 token，90 秒超时。识别可辨文字、主体、图表关系和关键数字，明确不确定项。不是用直接 LLM stream 冒充 Agent。
- `followup → whenIdle → 本次 turn/end.kind=completed → 同一 turn 的有效文本` 全部满足才成功；取消、截断、错误、工具请求、空输出拒绝。结束后释放 Agent；清理再次失败时保留原始错误和清理错误。
- 按机器人串行处理图片消息，对在途及已保存消息去重，正常群问答不等待后台识图。成功后把原消息文字与带「Agent 识别结果，可能有误，不是发言者原话」标记的图片文字合成一条 gzip 记录，进入原有全文索引、长期摘要和按需检索。
- SQLite 增量增加 `image_descriptions` 表，与文字记录同一事务保存图片数量、模型、usage 和 Agent Session 来源。不保存图片二进制到长期数据库；旧文本数据库和 schema 1 兼容，旧版本忽略附加表。不开启长期记忆时不创建新表或执行识图。
- 识图失败保留可用原消息文字并显示 `image-summary-failed`，纯图片不伪装成已归档；可以重新发送重试。关闭时取消在途和排队任务，迟到结果不写库。未完成转换的纯图片任务只在运行期排队，进程重启后不会自动补回，需重新发送；已有成功文字归档跨重启保留。
- 面板增加待识图计数、独立费用说明和识图失败提示。图片入库后原有群文字摘要仍单独产生调用。

Host 当前没有公开的临时 Agent 无持久化选项。独立 Session 会按 Host 会话/附件机制保留准备后的图片与输出日志，`dispose` 仅回收运行实例，不删除历史；文档已明确这一生命周期，不能声称只在内存处理图片。
