## 慢点与改动

从原群会话事件读取到一次查询进度的回合耗时 22,876 ms：先 `skill`，再 `dsh_idiom_game status`，最后模型生成回复；Python 工具自身 86 ms。独立重复运行 8 次真实 Python 裁判为 59–69 ms。证据说明模型往返是这条记录的主要等待，不能用重写 Python 或引入常驻服务替代修复。

新增 `plugin-src/host/channels/qq/idiom-fast-reply.mjs`，在受信 QQ 回合的 `llm/stream` 扩展点直接返回同一 Python 裁判结果。只允许渠道提供的当前纯文字：明确开局（如“猜成语，5次”）、进行中游戏的一条纯四字猜测、进度查询。图文、引用、多条合并发言、纠偏和复杂规则请求仍由原模型路径理解；缺词继续交给模型审核补录。裁判失败传播失败，不转交模型编造颜色。

仍由实际 DSH Agent 接纳输入并提交 assistant 记录到原 Session，因此没有建立独立游戏对话，也没有丢掉自己已经回复过的内容。固定操作身份与已有回执避免同一次请求重试重复扣次。本地结果 usage=0，不派发正文模型请求；未 @ 的接话判断和冷却保持原语义，仍可能调用判断模型。
