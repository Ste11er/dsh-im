# QQ 猜成语技能

状态：已集成并部署到当前 DSH，等待用户实群测试。用户来猜，Agent 主持；暂停好感度等后续集成。

出题职责：先由她自己想一个秘密四字词，再通过 `start.answer` 交给本地程序保存。程序不从题库随机抽词。之后每一手拆音、判色和记次数由程序完成；开局及终局换题各需要一次模型出题，普通已收录猜测不调用模型计算。

## 怎么使用

在 QQ 群 @ 她说「猜成语，3次」，随后每条提交一个四字词组。支持 **3、5、10 次**，默认 10 次；局中要求调整次数时保留已猜记录。当前规则按用户确认允许任意四个汉字，包括网络用语、口诀和重复字，不要求是成语。未 @ 的游戏消息继续受现有主动接话判断、冷却和忙时丢弃控制；测试建议先 @，避免将“没接话”误认为裁判计算失败。

她开局时提交自己想好的 `answer`（新词带 `pinyin`）；后续只需提交 `guess`，程序返回四行颜色、已用次数及剩余次数。普通回执不包含秘密答案；猜中、机会用完或要求揭晓时才返回本局答案，并标记 `nextQuestionRequired`。QQ 快路随后请模型想下一题并保存，成功才显示下一局已开始。换题失败时仍交付本手颜色及揭晓，明确下一题未准备好，不替换为随机题。不是四个汉字不计次数；缺词先确认读音并补录。

### 普通一手的本地快速回复

QQ 当前消息为“猜成语”“猜成语，3次/5次/10次”（也支持中文数字）、“猜成语进度”，或进行中游戏的一条纯四字猜测时，插件在 DSH 的 `llm/stream` 扩展点协调模型出题及本地裁判，不再等待模型读技能、调用工具、整理颜色。原生 Agent 仍记录 user/assistant 消息对，沿用当前群 Session。普通已收录猜测和进度查询 usage 为 0；开局/换题用当前回复模型想词及拼音，未收录猜测仅确认四字读音，按实际 usage 记账。

此路径只使用渠道传入的当前纯文字；图片、文件、引用、批量输入、多条合并发言和同回合新增纠偏不自动计为一手。非游戏文本和复杂规则请求继续交给模型理解。首次缺词时的读音请求只含固定拼音规则和当前四字，不含群聊历史、答案、成员标识或词库；最多输出 256 token。确认后通过同一个本地接口补录并判本手，之后同词无需再确认。读音不确定则请玩家补拼音，不补词、不扣次；程序/模型失败不编造颜色。同一已受理请求的重试复用本地回执，不重复扣次数。未 @ 的消息仍先通过群接话判断与冷却。

2026-10-29 实测：Python 单次 59–69 ms；真实已安装 DSH Agent/Session 的离线集成探针中，开局/猜测/进度分别 70/58/59 ms，模型派发次数均为 0。该测量不含 QQ 网络发送、生产大历史冷启动和未 @ 判断的延迟。探针及结果见 `outputs/runtime/qq-idiom-speed/native-fast-probe.*`。

四项独立判定：字形、声母、韵母、声调；先匹配🟩同位，再从剩余次数分配🟪异位，其他为⬜。默认四项都各自按次数计算。零声母不参与声母匹配，始终⬜；字形四格全绿即胜，不要求零声母也变绿。声调用 1–4，轻声 0，使用词典本调；一/不统一 yī/bù，不随语流变调。例：「星 xīng」拆为 x、ing、1；「耳 ěr」拆为无声母、er、3。

默认按拼写拆：y/w 算声母，iu/ui/un 保持拼写，v 归一成 ü。若双方使用其他口径，可开局传 `rules:{ywInitials:false,finals:"phonetic"}` 还原韵母；`phoneticCounts:false` 则仅字形按重复次数、其他三项按是否存在。改变判法要明确重开，不能悄悄修改本局规则。

## 随机分档与补词

内置 **29,502** 个四字条目，用于查读音和判分，不能代替她出题。常见档227个、一般档295个，其余为拓展档，分组不是实测词频。QQ 默认按 **70% 常见、25% 一般、5% 拓展** 只抽难度档，再由当前回复模型自己想该难度的词，不向模型发送词库供抽选。可要求固定档位或调整权重；新局沿用本局选项。出题模型生成结果必须包含四个汉字及四字拼音，程序验证保存；不合法则报错，不改用随机词。

未收录状态 `unverified-idiom` 保留兼容名称，仅表示缺词，不表示非法。AI 确认读音后调用 `add_and_guess`，一次补录并判本手；只入库、不提交猜测时仍可用 `add_word`。补词本身不扣次数，判本手只扣 1 次，拿到结果后不再调用 guess。支持数字拼音或带调拼音；默认新增到一般档。扩展词条按会话保存在本地，跨局和重启可用，其他群或 DSH Session 不共享。它标记为 `agent-added`，没有伪装成权威词典认证。已有词条读音冲突时明确报错，不覆盖原词典或已出题答案。

示例补词并猜：`{action:"add_and_guess",word:"原神启动",pinyin:["yuan2","shen2","qi3","dong4"],tier:"normal"}`。单独补词把 action 改为 `add_word`。只能写本游戏的结构化词表，不能传文件路径、代码、命令或其他会话标识。组合操作在本会话锁内执行，回执和落盘复用已有机制，重试不重复扣次。

## 技能与程序

- [技能说明](../skills/guess-idiom/SKILL.md)：精简的主持流程，由 DSH skill registry 注册。非 owner 回合的原生 `skill` 工具仍受既有权限限制，可通过本裁判的 `action:"rules"` 读取同一份说明，不放开通用文件读取。
- [Python 判分](../skills/guess-idiom/scripts/idiom_rules.py)：四项拆分、重复项绿优先、拼音规范化。
- [Python 游戏](../skills/guess-idiom/scripts/idiom_game.py)：保存模型答案、进度、机会、终局、补词、同操作回执复用、会话锁和原子落盘。
- [DSH 工具适配](../plugin-src/host/idiom-game-tool.mjs)：以实际 Session 派生状态编号、以实际工具 callId 派生操作编号；固定程序、无 shell、参数通过 stdin JSON，运行时 Python 只依赖标准库。
- [可下载技能包](../outputs/skills/guess-idiom.skill)：ZIP 格式，包含同一份技能和本地程序。DSH-IM 安装包也包含这些资源；仅解压技能包不会自动获得 DSH-IM 专用工具。

游戏状态默认在 `~/.dsh/integrations/dsh-im/idiom-games/`，由当前 `DSH_HOME` 决定根目录，文件名是 Session 哈希。每个会话独立游戏、扩展词表和锁；状态文件权限 `0600`，保存当前秘密答案和最多 64 个近期操作回执。不要把这些状态文件粘贴到群或当作 Agent 背景记忆；有本机文件权限的 owner 可读，所以它不是对本机管理员的保密边界。

重开已有 Session 保留本局；新建/切换 Session 会使用另一本局。数据不随群上下文 15 分钟过期而丢失，也不自动开启长期记忆。当前使用 Linux/macOS 的 `fcntl` 文件锁；Windows 原生 Python 未验证，不能据此宣称跨平台全部可用。Python 不可用、状态损坏、超时或取消时不编造判色；操作可能已落盘时先查 `status`，不盲目再次提交 guess。近期相同 callId 复用回执不重复扣次，新 callId 的同词猜测则是新一手。

## token 与权限

模型不加载 1.34 MB 词库。开局与终局换题使用当前回复模型及思考设置想词；普通已收录猜测本地拆音判色，不调用模型。新词使用同一模型做很短的读音确认，再本地补录判分。出题/读音请求均不携带整段群聊历史；没有另设模型。复杂主持请求的工具选择和正文仍消耗 token，未测量总体费用降幅。

普通群成员和自主接话只额外获准这个专用工具。通用 Python、run_code、bash、pwsh、文件操作、代理派遣继续仅 owner 可用；群消息与新增词条不会成为代码。自主接话判断器仍无工具，实际主持回复沿原群 Session 和发送控制执行。
