# 微信渠道已达成的能力（归档结案）

> **性质**：官方能力归档，用于**结案**——微信渠道的能力边界已核实清楚，后续不再作为待办来源。
> 本文件只记录**已核实的事实**；未达成项同样逐条列出，避免"已归档"被误读成"已满足所有目标"。
> 相关计划见 [微信个人号群聊补充目标与计划.md](微信个人号群聊补充目标与计划.md)（该文档已冻结验收，本文件不改写它）。
> 结案日期：2026-10-12。

## 0. 一句话结论

dsh-im 的微信渠道 = **腾讯 iLink 官方单聊机器人**。它在"私聊 + 多轮 + 富媒体 + 控制面"上是**已达成**的；在"普通群"上是**协议层不可能**，不是待开发功能。因此微信这块**结案**，群聊诉求转到 QQ（见后续 QQ 计划）。

## 2. 未达成（同样是已核实的事实）

| 未达成项 | 性质 | 证据 |
| --- | --- | --- |
| 普通微信群收发 | **协议层没有群概念**，不是开关问题 | `src/channels/weixin/weixin-runtime.mjs:409` 只接受 `kind === 'user'`；`weixin-bridge.mjs:393` 入站强制 `conversationType: 'direct'`；`weixin-api.mjs:14`、`:174`、`:326` CDN 走 `/c2c/` |
| 群内 @问答 | 同上，无群即无 @ | `docs/上下文增强.md:3`「微信当前只支持私聊」；`docs/方案/渠道原生能力建设方案.md:692`、`:785` |
| 未 @ 群消息 | **收不到**（与 QQ / WhatsApp 的"收得到但默认丢弃"不同） | 同上 |
| P0 五项发送控制 | 全仓库空白，非微信专属 | 发送预算/限频、安静时段、dry-run、账号级持久暂停、渠道侧原文落盘开关均无实现（详见计划文档第 3 节） |
| "个人微信号进普通群" | 官方通道是**机器人身份**，不是把个人号变成机器人 | 同上第一条 |

**关键边界**：微信上的"未 @ 群消息"属于**收不到**；QQ 与 WhatsApp 属于**收得到但应用层按"未点名"丢弃**。三者不可混写——这一点直接决定了群聊能力该在哪个渠道上做。

## 3. 为什么结案

1. 群能力不是配置项：iLink 消息项只有文字/图片/语音/文件/视频，且运行时只接受单聊目标；要靠"换通道"才能获得群能力。
2. 换通道只有两条路，都不在本次结论内：第三方个人微信协议（Wechaty/hook/桌面自动化，有账号风险，未核验）或官方其它平台。
3. **QQ 官方接口已提供"群消息（全量模式）"**（`GROUP_MESSAGE_CREATE`，机器人开启"接收所有消息"后群里每条消息都推送），且现有依赖 SDK 已支持该事件——这是**不需要第三方协议**就能获得"群 + 未 @ 消息"的路径。
4. 因此：微信作为**单聊渠道保持现状**，群聊与接话诉求转入 QQ 计划（另起文档）。

## 4. 后续

- 群聊与"偶尔接话"的规划见 QQ 渠道的补充计划（另行产出）。
- 微信渠道维持现状，不再投入群能力开发；如未来腾讯开放 iLink 群能力，再重新评估本结论。
