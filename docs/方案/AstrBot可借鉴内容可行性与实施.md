用户授权评估后实施；结合此前“一个功能一个功能集成，完成后先测试”的要求，首轮选择逐条消息轨迹，完成后等待真实 QQ 验收，再进入下一项。其余条目不是本次完成声明。

## 首轮影响面与契约

入口是 `QqHarnessBridge.accept`，轨迹按每机器人实例独立存储，以随机密钥 HMAC 关联会话路由和消息 ID，同一消息的普通事件和 @ 事件可看到多次尝试。独立群不会串记录。记录仅包含固定阶段/结果、时间、计数和哈希后的 Session/Turn/工具/错误码，不记录正文、提示词、工具参数、工具返回内容、路径、URL、凭据或配置。

桥接层观测访问、背景记录、接话判断、绑定后的宿主 Session、发送回执；冷却合并后的回调显式保留原轨迹上下文。共享 HarnessClient 新增可选 `onTurn` 元数据回调，由已关联当前 prompt 的 tracker 报告真实回合；其他渠道不订阅，不修改消息或宿主控制权限。

管理接口在既有 QQ RPC 下新增 `bot.trace.set/list/detail/export`；前后端 endpoint 常量与参数校验同步。开启开关持久化于每机器人配置；轨迹仅保存在 controller 的内存对象内，机器人重连保留，Host 重启清空。关闭停止采集但允许查看/导出已有元数据。运行中关闭后，旧异步回调不得继续写入；重新开启也不接受上一代回调。

容量：每机器人 256 条、每条最多 64 个事件、24 小时有效期；导出最近最多 50 条 JSON。超出容量淘汰旧轨迹，记录淘汰和事件截断计数；不阻塞消息或触发模型调用。以上为首轮诊断产品默认值，不是 QQ 平台限制，也不限制聊天数量。此轮没有磁盘持久化，所以不增加写库失败与迁移路径。

JSON 导出刻意只读取轨迹允许字段，不扫描凭据、配置或运行日志，因此不依赖从任意文本里猜测并遮盖秘密。输出用于本地下载，不向第三方上传。

## 验收与发布

验证需覆盖：保持安静、继续听、冷却合并、忙时丢弃、正常回执、发送失败/未知、重复投递、多群并发、容量/到期、关闭后晚到回调、导出脱敏和面板操作。Mock/本机回归与真实 QQ 证据分开记录。

先构建与回归，再备份旧 bundle 和现有用户状态，重载插件并验证管理接口。开关默认关闭，可由用户在 QQ 设置中开启。回滚可还原旧 bundle 并重启；本轮不迁移数据库，不改变群会话绑定、owner 权限、图片超时、猜词状态或长期记忆开关。关闭轨迹即可停止新增诊断采集。

功能验证结果记录在 `outputs/qq-impl/qq-message-traces-verification.md`，真实账号验收未完成前不进入第二项。

部署验证额外发现：工作区控制器会异步装饰管理返回值。轨迹 RPC 已显式 await；装饰器只对带 `bots` 的账号快照附加模型/预设目录，不再污染轨迹详情或诊断导出。这一小范围共享边界修正已加入使用真实工作区包装层的回归，并要求全量复验，避免仅测试裸 controller 而漏掉生产契约。

## 第二轮：空 @ 等待补充

用户于首轮交付后要求继续，开始实施第二项；这不被当作首轮真实 QQ 验收已完成的证据。

QQ 群聊空唤醒新增默认 30 秒静默等待，设置支持关闭/30 秒/60 秒。仅原群原发送者的下一条普通输入可继承唤醒；同时复核状态持久化、去重、当前访问权限、Session、工作区/世代、期限与取消信号。只存空唤醒元数据，不创建额外模型回合，补充仍使用实际发送者权限和自己的 QQ 回复目标。语义不扩展至私聊或普通带正文的 @。

新增一项账号配置和 `bot.empty-mention.set` RPC，前后端同步。权限/工作区控制器在成功提交后通知 QQ 清理等待；失败提交保持原状态。断连、暂停、停机或审批/问题到来时清理；Host 重启不恢复等待。无数据库迁移，旧配置缺省 30 秒，显式 0 代表关闭。

本轮不做语音编码、TTS 提供方接入、混合检索或入站节流。第二项部署和测试后停在用户验收，不自动进入第三项。
