# QQ 大肥鱼语音输出计划

日期：2026-10-26。状态：**仅规划，未实现、未启用、未调用收费语音服务**。下一步任务组：`QQ-VOICE`。本计划不创建独立 Codex 聊天或定时任务。

## 1. 用户目标与建议范围

让“大肥鱼”在当前 QQ 群会话中发出可播放的语音，声音与现有人格相符，能表现开心、得意、害羞、委屈、关心等自然情绪，并记得自己说过的内容。

建议分两阶段：先做用户明确要求时的语音回复，验证可发送、可播放、音色满意和耗时；随后开放她自主选择语音的模式。是否启用、使用哪个 TTS、哪个音色及何种输出模式，由管理设置决定。以下默认值均为规划建议，尚未应用。

首版覆盖被 @ 回复和未 @ 主动接话的真实回复路径，二者共用原群 Session；接话判断器继续只判断，不合成或发送语音。用户明确要求先做哪个模式，可在实施时调整顺序。

语音识别输入、实时语音通话、唱歌、声音复刻及训练专属音色不列入本轮交付；这些不是文字转语音的必要前置。

## 3. 建议交互与配置

沿用现有 QQ 机器人设置，增加“语音输出”部分：

- 使用状态：关闭、仅明确要求、自主选择。未配置时关闭；自主选择不设置随机概率，由真实回复 Agent 结合语境决定。
- 合成设置：提供商、对应模型、可用音色、语速；有情绪/风格控制能力时显示对应选项，不支持时说明能力范围。
- 输出形式：文字＋语音（建议首个测试模式）、仅语音。文字＋语音先送文字，语音随后作为同次回复的补充；不是保证 QQ 客户端能边生成边播放。
- 范围与调试：群聊/私聊适用范围、试听、最近一次合成/上传/发送耗时、失败阶段与状态。试听使用公开自拟句子，不发送到群。
- 凭据走已有凭据库，配置只保存引用；保存校验模型、音色及参数组合，不把明确非法配置默默替换成默认模型。

需要用户在实施前选定：**TTS 服务及地域、音色、自主还是点名触发、是否保留文字**。可先用同一组公开句子试听开心、安慰、嘴硬和普通说明四种语气，再定音色。

## 4. 回复链路与契约

建议链路：当前群消息 → 既有接话判断（仅未 @）→ 原群真实回复 Agent → 已决定的回复文字/语音意图 → TTS → 必要格式转换 → 当前 delivery 的 QQ 语音发送 → 回执与自身回复记录。

语音意图由同一个真实回复 Agent 给出，避免单独启动一个模型来决定“是否发语音/什么心情”。拟采用 QQ 专用语音工具，接收要说的文字与可选语气，合成并登记当前回合的语音产物；工具注册与暴露方式实施时按原生工具/产物契约确定。工具完成只能表示合成与登记完成，QQ 发送成功必须另有平台消息回执。

工具仅对实际 QQ delivery 开放，绑定当前 bot、群、Session 和 Turn；不能通过模型参数指定其他群。自主接话的工具白名单按同一能力接入；独立判断器仍保持 tools 为空。

`spokenText` 是真正要念出的内容，角色动作、语气指令作为单独元数据，不朗读“鲸尾晃了一下”等舞台说明；无需另一次模型改写。代码、长网址、表格等内容优先保留文字，是否口头概括由原回复 Agent 明确决定，不使用粗暴删除或静默截断改变答案。超出服务硬限制明确报告；产品长度建议须可调整，并说明哪些内容保留在文字中。

同次回复的文字、语音、表情包共用交付身份。群上下文记录实际成功发出的内容：仅语音时也记录对应口述文本；文字与语音相同则不重复注入。未发出的语音不能被记录成已经说过。仅有上传成功而无消息回执，不能当作已发送。

已知需要回归：当前 `finalAnswerOnly` 会清理工具前的助手文字；不能让新增语音工具导致最终文字答案、来源链接或口述内容消失。应验证工具前后文本与最终交付的一致性，而不是只测试生成了音频。

## 5. 情绪、速度与失败语义

情绪来自现有人格与当前对话，由 TTS 能力呈现。服务支持风格指令时传入短指令，不向 TTS 发送整份群历史、成员标识或长期记忆。仅普通 TTS 可用时标记为普通语音，不宣传已实现情绪控制。切换新服务前确认实际传输的文字、目的地、地域与费用；已有聊天模型授权不自动覆盖新增 TTS。

语音采用完整消息上传的首版路径；即使 TTS 支持流式，也要完整生成到 QQ 可接受的媒体才能发送，不能把 TTS 首包耗时当作群里可听见的延迟。

优先保持当前文字回复速度：文字＋语音模式不等待合成才发送文字。语音任务仍属于受跟踪的同一轮交付，遵守原忙时丢弃、取消、群会话绑定、暂停、安静时段和发送预算；每条实际 QQ 消息纳入既有计数。合成结束后再次检查仍可能变化的发送条件，不在暂停、改绑或取消后补发旧语音。

分别记录：模型完成、文字发送、TTS 耗时、转换耗时、QQ 上传和消息回执；统计包括失败、取消和超时。用同样的公开短句对比文字基线和语音路径，报告 P50/P95 与样本数。首阶段先测量，不承诺未经实测的秒数或费用。

失败区分：TTS 未生成、编码转换失败、上传失败、消息发送被拒绝、发送结果未知、用户取消。仅语音模式在确定尚未发送时回退文字，并标记语音失败；文字已发时不再重复全文。发送超时但可能已投递时保留未知状态，不盲目重发语音或全文。重试仅覆盖已识别、可安全恢复的阶段，并给出总时限；不叠加 SDK 与业务层的重复发送重试。

合成音频默认只做当前交付的短期临时文件，完成或取消后清理；首版不建立长期语音档案或全群音频缓存。以后确需缓存，另定按模型、音色、风格和文本区分的缓存键及保留期限。

## 6. 下一步任务拆分

| 编号 | 任务 | 交付与退出条件 |
| --- | --- | --- |
| QQ-VOICE-01 | 核验 QQ 语音出口 | 用已获准的公开短音频验证当前账号群聊的格式、回执与手机播放；分别记录上传、消息发送、用户听到。未通过则明确平台/账号阻碍，不伪装普通文件成功 |
| QQ-VOICE-02 | 选定 TTS 与试听 | 对比公开短句的音色、情绪、完整合成耗时和费用；用户选定服务/音色；获得所需服务权限及凭据配置，仍不重放私有群历史 |
| QQ-VOICE-03 | 配置和合成能力 | 接通设置、凭据引用、参数校验、试听、可取消合成及音频格式验证；状态区分未配置、可用、失败 |
| QQ-VOICE-04 | 同会话语音交付 | 接通真实回复 Agent 工具/产物、QQ sendVoice、发送控制及自身回复记录；被 @ 和主动接话共用同一实现；判断器不暴露语音工具 |
| QQ-VOICE-05 | 异常与性能回归 | 覆盖超时、失败、取消、改绑、暂停、预算、多媒体混合及工具前文字保留；给出分阶段耗时和文字基线对比 |
| QQ-VOICE-06 | 部署与实群验收 | 备份原配置和群 Session 绑定；先开启点名触发、文字＋语音，用户确认能听且语气合适后，再按选择开放自主语音 |

01 与 02 完成后才能锁定格式转换路径和默认模型；03、04 合拢后执行 05、06。本次仅登记这些任务，不执行。

## 7. 影响范围、验证与回退

预计修改 QQ config-store/controller/runtime/bridge、QQ 管理 RPC、客户端设置与状态归一化；新增 QQ 合成服务和工具上下文。共享产物模块仅在它确实缺少音频呈现契约时扩展，并验证其他渠道原行为。飞书实现只作为参考，未经需求不顺便迁移。

验证分层：纯配置和服务契约测试 → 真实 TTS 公共句子探测 → QQ API 回执 → 手机端播放 → 情绪试听 → 同会话追问和耗时统计。模拟测试与公开服务实测分别标注；最终部署运行相称的回归、构建和包校验。

关键实群用例：

1. “大肥鱼，用语音跟大家打个招呼”：收到可播放的原生语音；接着问“你刚才说了什么”，能在同群会话准确承接。
2. 开心、委屈、安慰、认真说明各试听一次：用户判断自然度，不把模型自评或文件生成当作音色验收。
3. 未 @ 自主接话允许选择语音，但语义完整性判断、冷却和忙时丢弃继续生效；关闭语音即恢复文字/表情路径。
4. 合成失败、取消或发送结果未知时不重复刷屏；查询、代码、长来源链接仍能完整交付文字。
5. 合成中暂停、解绑/改绑或结束会话，旧语音不投递到新会话；语音文字不会跨群进入记忆。

回退先关闭语音，再停止/取消受跟踪的语音任务；保留原人格、聊天模型和群 Session 绑定。若涉及代码回退，使用新增配置向后兼容的关闭状态与部署备份；不批量覆盖其他已变更配置。已计费的合成请求与已发出的群消息不能因关闭开关而撤销，需如实保留状态。
