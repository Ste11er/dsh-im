# QQ 群聊自主参与

## 图片下载超时丢弃（2026-10-29）

为避免慢图片占住回复，QQ每次图片处理从首张图片实际开始下载起，共享 **5秒** 下载预算，包含接收响应正文；不会每张图片重新给5秒。群聊@、私聊、未@判断与回复、所选历史图片都受此预算约束。已成功下载供判断和回复复用的图片无需再次下载；预算不限制模型思考或正常文字回复时间。

超时会取消实际HTTP请求并停止等待，丢弃本条处理、标记已消费、释放处理队列；不向群或私聊再发送下载失败提示，不调用模型猜图片。超时尝试涉及的图片引用从近期背景中移除，保留文字及图片已丢弃标记，防止下一句聊天再次触发同一慢图。群接收诊断显示“图片下载超时，已丢弃本条处理”，状态统计记录超时丢弃数。5秒是当前回复延迟的产品默认值，不是QQ文件大小限制；原有附件大小、来源与访问权限校验保留。其他下载错误仍按原错误语义报告。

QQ → 对应机器人设置 →“群聊自主参与”，可以启用/关闭，修改每群候选评估冷却秒数、选择独立判断模型，再保存。当前机器人按本次需求开启，默认冷却 180 秒；其他未配置账号默认关闭。

触发来自新收到的未 @ 群文字或图片，不是定时群发。需要平台已投递全量群消息，并开启短期群聊上下文。不做概率抽样，模型结合近期片段判断“继续听”“可以接话”或“保持安静”。只有语义已经完整且适合参与时才生成回复。按用户确认，此判断仅用于未 @ 的主动接话；被 @ 的普通聊天仍立即走原回复链路，并开始本群冷却。

同一人把一次发言拆在多个消息框时，尚未处理的片段按顺序保留，不因停顿或消息框边界而自动视为说完。按当前语境宽松判断“是否已经足够自然回应”，不要求语法完整或把意思全部展开。同一句“这张图里的公式”，在机器人刚问“想了解公式还是配色？”之后可以直接接话；在对方明确说“先别回，我分几条发”、问题还没交代时则继续等。短句、反问、省略、接梗、表情和独立图片都可回应；拿不准还有没有后文但已有合理回应点时倾向允许简短接话，不凭固定短语机械等待。模型无法预知未来消息，仍可能误判。

冷却限制模型评估频率，评估一次即进入冷却。冷却或判断期间到达的新消息会合并为本群最新候选，最早在既有冷却结束后评估；不会每来一条就重置计时。新片段会使尚未完成的旧判断失效，晚返回的旧判断不能生成回复。没有新输入时，“继续听”不会被定时器冲刷、重新评估或自动转成回复。真正开始生成回答后，沿用忙时不排队回复的规则。冷却按群隔离、保留于当前进程，重启后重新计算。

未完成片段与近期上下文共用既有边界：每群最多 20 条、每条最多 512 字符、总注入最多 8192 UTF-8 字节、保留 15 分钟、最多 100 个群。超出范围会淘汰，不能无限等待或保留。其他人发言仍作为背景，不拼成同一个人的话。已处理的提问和机器人成功回复保留为背景，避免被再次当作当前提问。

冷却可调整，为正整数秒，不静默裁剪非法值。保存判断模型/冷却/开关会取消待完成的旧候选，后续按新参数生效。关闭群聊上下文会暂停自主参与。设置和人格、模型选择独立，重启及重新绑定保留。

仅考虑访问策略允许的真人普通群文字及图片；重复消息、机器人消息、斜杠命令和文件消息不触发评估。群里已有被 @ 的任务、审批、问题或菜单操作时不插话。判断期间新的 @ 会取消旧判断，优先处理点名；真正生成回答期间的新普通群问句仍按既有忙时规则丢弃，控制命令可以中止。

纯图片也可以进入判断。图片通过受限下载、格式校验、压缩和 Host 附件准入，真实传给支持图片的判断模型及回复模型；本次发言的图片优先，其余预算选近期背景图片，序号与实际输入对应。一次判断和回复复用已下载的原图字节，回合结束释放，短期群缓存只保留懒加载引用。若判断/回复模型仅支持文字，则用已配置的“长期记忆：图片总结模型”生成明确标注来源的转述；该操作本身不写入长期记忆，不依赖长期记忆开关。需要选择支持图片的总结模型，否则明确失败，不假装看见。下载失败和超限保持错误，不当作模型决定安静。

“自主参与：判断模型”未单独选择时跟随回复模型。判断始终是独立、无工具的短调用，只输出接话、继续听或安静；同意后才在本群已有会话中调用回复模型。判断输入明确区分当前发言数组与近期背景，背景包括机器人已经成功发送的文字及附件发送记录，避免把旧问题重复当成新输入。判断失败会显示错误，不当作保持安静或自动改用回复模型。判断模型与长期记忆模型独立。旧版配置的概率字段读取时迁移移除。

判断器的最终系统提示仅保留分类职责，清除继承的聊天风格上下文与工具。人格基线作为引用资料供识别称呼、兴趣，不再追加为判断器自己的系统角色；真正的群回复仍使用原人格。群友要求“直接回话”只是判断素材，不能把分类器变成回答者。若返回“判断标记＋聊天正文”或纯聊天正文，仍明确报 `qq-judgment-invalid`，面板说明“尚未调用 QQ 发送接口”；不截取任意正文冒充合法判断，也不自动重跑模型或重发旧群消息。

自主回复与被 @ 回复使用同一个 `group:groupOpenid` Session 绑定。她能看到该会话历史中自己的 assistant 回复；正常群问答的提问和成功发送的机器人回复也进入短期背景，供后续判断使用。不同群及私聊仍然隔离，用户主动 `/new`、切换会话或工作区时沿用原有会话规则，不额外清空历史。

自主回复这一回合临时使用原生表情检索、已选表情回传、本群记忆查询，以及 Host 已配置的 `web_search`、`web_fetch`。按实际 Host turn 绑定工具守卫和取消；回合结束恢复普通会话的工具呈现。联网搜索按需使用：明确要求搜索、核实或涉及最新事实时查询，优先官方来源、附实际链接；普通闲聊不额外联网。搜索/网页读取继承原生工具的限时、结果预算、取消和公开地址限制，失败如实说明。配置没有注册某个工具时，不向模型宣称它可用。通用操作和 `run_code` 在自主回合不可用，不把普通群聊或网页指令当命令执行。合适时可以发表情，仍走已有权威文件登记和 QQ 原生图片链路；表情仍仅使用本地缓存。详见[联网搜索](QQ联网搜索.md)。

判断与回复会产生模型调用费用；冷却限制评估调用。只有判断使用临时 Host 会话；正文、工具调用与回复保存在本群正常 Session。会话历史按 Host 保留规则处理，不等于启用长期群记忆。长期记忆开关不改变。后台自主发送遵守账号暂停、发送预算、安静时段与 dry-run；发送前重新核对设置、访问权限、工作区和发送门控。不会把被阻止的闲聊排队到稍后群发。

设置面板显示候选数、保持安静次数、继续听次数、已接话数和错误数，均为本进程统计。失败保持明确诊断状态，不冒充模型决定安静；混合的沉默标记不发送到群里。QQ 平台仍可能依据权限、被动回复窗口或配额拒绝，沿用既有发送结果与不确定状态处理，不盲目重发。

测试时正常聊天观察即可；180 秒冷却且模型自主判断时，暂时没接话不一定是故障。可暂时缩短冷却后保存测试，再按体验调整。@ 问答、owner 命令权限与私聊访问策略保留。被 @ 的普通回复另外执行[电脑命令 owner 校验](QQ电脑命令权限.md)：普通成员不能借助模型工具操作电脑，仍可聊天、联网和使用缓存表情。

延迟或重连后收到的旧群消息按原始 `timestamp` 核对 QQ 的 5 分钟被动回复窗口；过期消息可照常进入已开启的长期归档，但不加入近期背景、不触发自主接话。发送前也会再次核对窗口。缺失或非法时间戳会报告错误，不补成本地接收时间。平台仍返回窗口过期时，面板提示发送一条新消息。

发送遇到明确的连接建立超时，会对同一请求与消息序号重试一次；连接中断、请求超时、响应读回失败等结果不确定的错误保留失败，不重复发送。面板会显示连接超时或回复窗口过期的具体原因。恢复策略和实测边界见[发送失败验收记录](../outputs/qq-impl/qq-send-recovery-verification.md)。


## @ 事件去重与各群接收诊断（2026-10-29）

普通群消息的接话判断本身不再将消息 ID 标为已消费；只有实际接管回复之前才持久标记。这样同一条消息先以 `GROUP_MESSAGE_CREATE` 被判断为保持安静/等待，随后以同 ID 的 `GROUP_AT_MESSAGE_CREATE` 到达时，@ 仍能走正常问答。实际回复已开始的消息继续去重，避免平台重推造成再次生成或重复投递；原有忙时丢弃语义保留。

QQ群之间的判断、冷却与忙状态继续按 conversation key 隔离。一个群正在判断或回复不代表其他群也在忙；跨群 @、普通接话的并行回归已覆盖。当前生产设置是账号级开启，不存在只允许最活跃群的本地开关。

QQ 设置新增“各群消息接收诊断”：分别显示平台事件中的 @/普通数量、本地识别的 @/普通数量和最近处理状态。数据从本次连接启动计数，最多保留最近 100 个群的诊断，不改变群消息处理容量；不保存正文、成员 ID 或完整群 ID。显示尾号来自平台不透明群标识，不是 QQ 群号。

接收计数位于 SDK 消息进入的第一个中间件、归一化和清理之前。当前 SDK 只对未被 message dispatcher 消费的事件发 `rawEvent`，因此不能用那个事件监听统计已处理消息；回归测试按 SDK 的实际单路分发契约执行。没有普通事件的计数只能说明本次尚未观察到，不等于已证实平台权限关闭；需要在目标群发送普通消息核对。其他群的 @ 能到、普通消息持续不到时，由该群管理者核对 QQ 侧的全量消息接收授权；本地自主参与开关不能让平台发送未获准的消息。

说明与验证见 [多群接收与 @ 修复记录](../outputs/qq-impl/qq-multigroup-fix-verification.md)。

### 逐群实测定位（2026-10-29）

受影响群在用户发送不 @ 的 `test` 后，普通事件计数仍为 0；随后同群 @ 测试收到 1 次 `GROUP_AT_MESSAGE_CREATE`，本地识别为 @ 并成功回复，接话判断候选计数为 0。已证实这次普通消息没有进入本地首个消息中间件，不能归因为模型保持安静或其他群忙。仍须由群主核对 QQ 中该群的消息接收范围；未读取其手机设置，不能断言开关当前值。

群主在手机 QQ 打开“群聊设置 → 群机器人 → 当前机器人 → 管理”，检查“机器人可获取的群聊消息范围”并选择“获取群内全部消息”；每个群单独设置，保存后发一条新的不 @ 消息，核对普通事件和判断计数。入口依据[QQGroupAuthorize 作者提供的操作指引](https://forum.olivos.run/d/932-qq-bot-qqgroupauthorize)；QQ 官方页面本次无法直接读取，界面名称应以当前手机 QQ 为准。本功能对普通入站事件作被动回复，与定时主动推送权限是不同路径，不应把二者混同。

### QQ 连接恢复的诊断与请求超时

连接专用的认证请求沿用 SDK 的 10 秒默认值，获取 WebSocket 地址沿用 30 秒默认值；计时覆盖响应头和完整响应正文，超时或停机都会取消实际请求。SDK 原有 token 缓存、singleflight、后台刷新和重连退避继续生效，HTTP 429 等限流仍使用原有退避。

`connection.status` 中的 `gatewayTransport` 现在区分 `token/gateway/hello/ready/connected` 阶段，保留当前 runtime 最近一次断开原因、关闭码、时间以及最近 32 次状态变化。服务端要求重新连接也会计入重连次数；连接恢复会清除当前故障状态，但保留历史原因。记录不包含群聊内容或凭据，runtime 被重建时会重置，断开元数据另写入 DSH 本地运行日志。

`lastMessageEventAt/messageEventsReceived` 是 WebSocket 收到消息事件的证据，`lastHeartbeatAckAt` 只证明心跳有回执。群内长时间无人说话本身不会触发重新连接；只有连接故障和协议超时才进入恢复。
