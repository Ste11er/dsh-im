# QQ 群聊长期记忆

长期记忆把「近期原文、模型摘要、压缩原文归档、按需检索」接在现有短期群聊上下文上。两个开关均按机器人保存，默认关闭。先开启[短期群聊上下文](QQ群聊上下文.md)，再在 QQ 机器人设置中开启「长期群记忆：本地压缩归档、模型摘要与按需检索」。新消息从启用时开始保存；之前已过期或因重启丢失的短期缓存不能补回。

## 总结模型选择

QQ 机器人卡片的长期记忆区域有两个独立选择器：「长期记忆：图片总结模型」用于图片转文字，「长期记忆：文本总结模型」用于群聊文字摘要。可选择模型及思考强度，选择后自动保存；长期开关关闭时也可以先配置。图片模型必须支持图片输入，保存失败时保留原选择。

每项都可单独恢复「跟随机器人 / Host 默认模型」：先跟随机器人模型，机器人未指定时再跟随 Host 默认模型。设置不会改变正常聊天模型或启用长期记忆。修改用于后续启动的任务，不需要重连、重启或 `/new`；已运行任务沿用原模型，历史结果不会自动重做。配置按机器人持久保存，重新绑定及扫码时保留。

配置字段为 `groupMemoryModels: { text: ModelSelection | null, image: ModelSelection | null }`，缺字段表示跟随默认。管理端点 `bot.group-memory.model.set` 参数为 `{ botId, kind: 'text' | 'image', model: ModelSelection | null }`；`null` 恢复对应项默认规则，非法值报错。每份结果仍记录其实际模型。

## 保存和问答

- 近期问答继续使用每群最近 20 条、15 分钟内的短期背景。
- 获准访问的群消息，其 SDK 规范化后的文字正文通过 gzip 无损压缩写入本地 SQLite；保存消息 ID、发言者、接收时间和来源序号。包含被 @ 的提问，不包含附件二进制、原始 QQ 网络包或机器人回复。图片先由独立视觉 Agent 转换为文字，再与同条消息的文字一起保存，纯图片也支持。
- 后台对超出短期窗口的待处理原文生成模型摘要，保留事实、日期、数字、决定、待办、冲突及来源序号。摘要属于有损提炼；归档原文仍然保留。
- 被 @ 时只检索当前群的相关摘要，并补充最近一条摘要；询问原话、细节，或者没有匹配摘要时，再检索少量相关原文。不会把整个压缩文件或全部历史放入模型上下文。使用问题到达时的序号边界，排除这次问题本身和之后的消息。

群消息依照现有访问策略过滤，私聊不进入群记忆。未 @ 的命令文字只作为数据，后台摘要不能执行工具、命令或向 QQ 发消息。历史以不可信会话数据传入模型，不提升为系统指令。检索使用中文双字词和英文词的全文索引，不能保证召回每种同义表达。

图片任务仅在长期记忆及短期上下文均开启时运行，按机器人串行处理并去重，不阻塞正常问答。Agent 提取可辨文字、画面主体、图表关系、关键数字，并区分原文与推测；归档明确标为「Agent 识别结果，可能有误，不是发言者原话」。模型须支持图片；数量、下载和压缩预算沿用 IM 图片设置。独立 Agent 禁用工具，最多一步模型请求、输出最多 1200 token、90 秒超时，正常结束且文字有效才归档。识图本身也产生模型费用，与后续群文字摘要分别计算。

识图失败时已有消息文字仍归档，纯图片不会被伪装成已保存；面板显示图片识别失败，可重新发送图片重试。关闭功能会取消在途识图，迟到结果不会提交。待识图计数表示正在处理或排队的消息数；识图未完成时的提问不会读取未来结果。长期库只保存文字、图片数量、模型用量和独立 Agent 会话来源；Host 会保留独立识图 Session 及其图片输入，生命周期遵循 Host 会话与附件规则，释放 Agent 不等于删除该日志。

## 调度和成本

| 项目 | 当前初始值 |
| --- | --- |
| 后台检查 | 每 60 秒检查一次；没有到期原文时不调用模型 |
| 自动摘要条件 | 原文已接收 15 分钟，或超过每群最近 20 条 |
| 每群自动尝试间隔 | 至少 15 分钟，按批次处理，并非固定每 15 分钟删除历史 |
| 每轮与每批 | 每轮最多 4 群，每群最多 40 条，序列化原文最多 24 KiB |
| 模型 | 图片识别用图片总结模型，群聊文字摘要用文本总结模型；未指定则跟随机器人/Host 默认 |
| 单次摘要 | 输出最多 1200 token，90 秒超时；落盘摘要最多 6000 字节 |
| 问答中的长期背景 | 含标签与转义最多 8 KiB，另有短期背景最多 8 KiB |
| 原文补充 | 最多 3 条，每条最多 1200 个 JavaScript 字符单元；截断有标记 |
| 单条原文归档上限 | 1 MiB UTF-8；超出时明确报告归档失败 |

以上是本实现的产品初始预算，不是 QQ 或模型平台限制。gzip 节省本地磁盘，不减少解压后的模型输入 token；省下重复读取成本的是摘要与选择性检索。后台摘要本身会产生模型费用，问答附带的摘要和原文也计入输入。模型返回 usage 时随摘要保存，未提供则记为未知；没有据此承诺具体金额、节省比例或回答质量。

摘要请求独立于用户会话，不创建 Agent 或使用工具，也不改变会话绑定。面板的「立即生成摘要」可处理尚未到期的原文，遵守同样的批量预算。请求返回只表示已受理；以「正在生成摘要」、摘要数、待摘要数及错误状态判断结果，面板按现有轮询刷新。

失败时原文保持待摘要状态；自动尝试连续失败 3 次后暂停该群自动重试，可用手动生成再次尝试。没有正常结束、输出截断、空结果、工具请求、取消和超时均不记作成功摘要。落盘失败单独报告「归档失败」，不声称消息已保存。损坏或版本不支持的数据库会报错，不自动覆盖为新库。

## 本地存储和生命周期

默认路径为 `~/.dsh/integrations/dsh-qq/bots/<botId>/group-memory.sqlite`，使用插件自定义数据目录时随该目录变化。数据库文件权限为 `0600`，正文 gzip 压缩，摘要和检索索引仍是本机可读数据，未加密。无自动清理期限；需要为增长的磁盘占用安排备份和管理。SQLite 运行期间可能同时存在 `-wal` 和 `-shm` 文件，备份时先停止对应机器人或整个 DSH 服务，避免仅复制主文件遗漏未合并记录。

关闭长期记忆会停止新归档、后台摘要和检索，取消在途摘要，保留已有数据库；重新开启或重启后恢复使用。关闭短期上下文也会暂停长期记忆。`/new`、`/clear` 只影响原有会话机制，不删除群记忆；在管理面板显式删除机器人时才删除其归档数据库及 SQLite 附属文件。若要停用新功能并回退版本，先关闭长期记忆，保留数据库备份。

控制端点为 `/qq` 下的 `bot.group-memory.set`，参数 `{ botId, enabled: boolean }`；手动摘要为 `bot.group-memory.compact`，参数 `{ botId }`。配置开启时保存 `groupMemoryEnabled: true`，缺字段表示关闭，非法类型报错。状态提供 `groupMemoryEnabled` 及 `groupMemory: { enabled, archived, summaries, pending, lastSummaryAt, summarizing, lastError }`；未打开过数据库时计数为未知值 `null`。公共状态不包含消息、摘要正文、群或成员 ID。

## 实测方法

1. 在测试群普通发送一条独特事实，例如「本次长期记忆测试代号是海风317」，不要 @ 机器人。确认机器人不回复，面板「已归档」「待摘要」增加。
2. 点击「立即生成摘要」，等「正在生成摘要」结束，确认摘要数增加、没有错误。请求被受理不等于摘要已生成。
3. 等待短期缓存过期，或先关闭再打开短期上下文以清空短期缓存；保持长期记忆开启。需要隔离已有会话历史时，由 owner 使用 `/new`。
4. @ 机器人询问「本次长期记忆测试代号是什么？」。检查答案是否正确，并测试另一个群不能查询到该事实。重启 DSH 后可以重复查询，检查持久恢复。

## 简短概览与按需查询（2026-10-24）

回复默认仅注入最多 1200 UTF-8 字节的概览：按当前问题相关度挑选一段摘要摘录；没有匹配时只提示可以查询，不无条件追加最新摘要或原文。需要精确事实时，Agent 通过 `dsh_qq_memory({query:"具体关键词或原文"})` 搜索当前群的完整索引；最多 2 条相关摘要和 2 条相关原文，单条正文约 900 字节，整个查询引用框最多 3072 字节。工具直接渲染引用文本，避免重复 JSON 转义放大预算。摘要截断有标记，图片识别内容保留 Agent 来源提示，完整原始档案继续保留。

查询能力绑定当前群、当前请求的历史截止序号、真实 Session/Turn 与实时记忆开关；工具不接受其他群或账号参数。普通闲聊直接回复，真正需要历史时才增加查询步骤。此次部署将现有群聊切换到新会话，以摆脱旧提示累计；原会话与长期档案保留，旧绑定有备份。回复模型经用户确认切到官方 DeepSeek Flash，思考 Off。

群聊正在处理/投递回复时，新普通提问（含图片/文件）标记已见并丢弃，不排队、不自动纠偏、不下载附件。控制命令、必要的审批/提问答复仍可用。私聊沿用已有设置。
